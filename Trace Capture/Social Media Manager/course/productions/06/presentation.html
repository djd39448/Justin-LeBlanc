LESSON 06

Build specification and plan

Turn the architecture into a testable build contract and plan.

Video · Transcript · Captions

Visual outline
  1. Make the agreement buildable: A specification turns settled decisions into a contract an agent can follow.
  2. “Validate the form” is not enough: Replace a vague instruction with an observable response.
  3. Give every claim a check: A stable acceptance ID connects the requirement to its evidence.
  4. Protect what the work must preserve: A change contract includes boundaries and a way back.
  5. Put dependencies before parallel work: One possible route from a shared record to verified behavior.
  6. Ready for a fresh agent?: Test the handoff before execution begins.
  7. Define the first release: Start with a small owner outcome, then draw its boundary.
  8. Show the failed form state: A useful specification says exactly what the visitor sees.
  9. Trace A-02 all the way to proof: Use a requirement, a check, an environment, and an honest claim.
  10. Compatibility before recovery: Know what stays intact and which actions cannot be undone.
  11. Parallel work needs a shared foundation: Coordinate dependencies, then let independent work proceed.
  12. Walk three cases through the contract: Use examples to expose the rules that are still missing.
  13. Give the plan to a new reader: The fresh-agent test exposes consequential ambiguity.
