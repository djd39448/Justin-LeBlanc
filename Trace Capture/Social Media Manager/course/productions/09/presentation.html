LESSON 09

Autonomous builds and recovery

Plan checkpoints, boundaries, recovery, and a morning report.

Video · Transcript · Captions

Visual outline
  1. Autonomy stays inside an agreement: Permission to continue does not mean unlimited authority.
  2. Leave a checkpoint that survives the session: Each verified slice should make the next start easier.
  3. A blocker becomes a specific owner action: Record the boundary, then continue authorized independent work.
  4. Recover the state before retrying: An interrupted request may already have taken effect.
  5. Keep capacity for the finish: Dave’s reserve example is configurable, and actual permissions still apply.
  6. Report proof the owner can inspect: The morning report names completed work and the remaining uncertainty.
  7. Write the overnight contract: A long run starts with a bounded definition of done.
  8. Checkpoint before context disappears: Record enough reality for another session to continue safely.
  9. Keep the blocked integration inactive: A credential gap need not stop unrelated, authorized progress.
  10. A timeout is not a clean slate: Preserve uncertainty until the external effect can be reconciled.
  11. Use the reserve deliberately: The policy protects the work needed to finish safely.
  12. Make the morning review easy: Write for the person who was asleep while the work happened.
  13. Resume from the actual workspace: Compare the handoff with reality before choosing the next action.
