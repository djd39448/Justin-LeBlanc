# Routing, usage, and autonomous work

## Route by capability and cost

Confirm the available executors and actual task constraints. Use deterministic scripts or built-in tools for repeatable searches and transformations; qualified local models for suitable drafting or extraction; lower-cost capable workers for bounded ordinary implementation; and a qualified lead for architecture, shared contracts, ambiguous failures, security, integration, and final review. Avoid duplicate work and escalate when risk, failure, or ambiguity warrants it.

Give each worker a compact brief: objective, sources, exclusive scope, expected output, acceptance, and stop conditions. Parallelize independent work only. Reconcile results and inspect consequential changes before counting them complete. Record the actual route and usage when exposed. A requested model or workflow is not evidence it is available.

## Monitor what is actually observable

Check available usage before substantial cloud dispatch and after batches. When applying Dave's default policy, reserve 25% of the tightest shared allowance and stop discretionary cloud dispatch at 75% used. These are configurable preferences, not universal provider limits or proof of automatic enforcement. Honor a different user or project budget when specified. If the relevant allowance cannot be inspected, treat it as constrained: avoid discretionary cloud dispatch and continue useful work with deterministic tools or qualified local capacity; retain only the minimum authorized cloud work needed for safe completion and handoff. State the limitation rather than pretending a threshold was checked. Do not assume machines using one account have independent pools, automatically redeem reset credits, or spend on filler polling.

## Long-running execution and recovery

An authorized long-running build should name the governing spec, definition of done, scope, permissions, checks, checkpoints, deadline if any, and stop conditions. Choose routine reversible defaults within scope and record assumptions. Persist completed work and evidence at meaningful milestones, including revision, running state, exposed usage, pending or uncertain external effects, rollback, and next safe action. Use a durable work log rather than chat memory alone.

If an item needs the owner, record the exact blocker and required action and continue independent work. Before retrying an interrupted job, reconcile existing work, processes, durable state, receipts, and uncertain effects; do not blindly repeat an external send or accepted operation. Autonomy does not authorize new spending, credentials, destructive actions, or out-of-scope external changes.

Close with an honest report of completed and unverified work, evidence, actual routes and usage where exposed, unresolved effects, owner actions, rollback, and the next safe step. Do not claim success for a scaffold, mock, or unverified integration.
