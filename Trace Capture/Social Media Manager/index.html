01 / Workflow

Slow down once. Move fast after.

The workflow spends attention at the moment when misunderstandings are cheap. Once intent, architecture, and proof are agreed, the implementation agent gets a precise path instead of an invitation to improvise.

Conversation loop

Ends when the behavior and tradeoffs are mutually understood.

Spill→Mirror→Research→Decide→Agree

Delivery loop

Ends when the change is provable, recoverable, and restartable.

Baseline→Build→Verify→Prove→Compound
02 / Documentation system

Every document gets one job.

The power is not “lots of docs.” It is a clean separation between authority, design, execution, proof, operations, and history. Click a phase to see the files that carry it.

AGENTS.mdConstitution

Session rules

“What authority and guardrails apply?”

Read order, scope, resource boundaries, cost controls, engineering invariants, and what a session may not infer.

README.mdFront door

Current-state index

“What is true right now?”

A concise map of what is live, what is pending, how to run it, and where deeper authority and evidence live.

DECISIONS.mdMemory

Decision ledger

“What is settled—and why?”

Accepted, provisional, deferred, and rejected choices with rationale and the condition that would reopen them.

ARCHITECTURE.mdStructure

System model

“How does the system fit together?”

Boundaries, modules, sources of truth, contracts, dependencies, data flow, permissions, reliability, and security.

WORKFLOWS.mdBehavior

State over time

“What happens next—and when it fails?”

Happy paths, state transitions, retries, idempotency, reconciliation, time rules, side effects, and recovery.

BUILD_SPEC.mdContract

Requirements contract

“Exactly what must be built?”

Outcome, users, behavior, validations, compatibility, non-goals, preservation rules, acceptance, and deployment boundaries.

ACCEPTANCE.mdProof design

Acceptance matrix

“What observation makes this true?”

Stable IDs, scenarios, test layers, live-vs-mocked labels, rehearsals, artifacts, and explicit pending gaps.

KICKOFF.mdAuthorization

Executable brief

“What may this clean session do?”

Repo, base revision, branch, read order, baseline, locked decisions, permissions, forbidden actions, gates, rollback, and deliverables.

plans/Sequence

Dependency-aware plan

“In what order should we build?”

Preflight, contracts, owned parallel work, integration, verification, review, and explicit completion checkpoints.

PROGRESS.md / BUILD_LOG.mdLedger

Work state

“What happened, and what is next?”

Chronological implementation facts, current checklist, exact checks, blockers, and next slice. It is not product history.

CHANGELOG.mdHistory

Material change record

“What changed across versions?”

Dated material changes and pivots. Concise history—not a live-status claim and not a dump of every command.

docs/evidence/Record

Immutable proof

“What actually passed?”

Dated, sanitized commands, SHAs, counts, screenshots, provider observations, failures, and exact unverified gaps.

RUNBOOK.mdOperations

Operate and recover

“How do we run this safely?”

Start, inspect, stop, retry, reconcile, back up, restore, contain incidents, roll back, and interpret failure states.

HANDOFF.mdContinuity

Restartable context

“Can a new agent continue cold?”

Exact revision, current truth, verified vs unverified, running state, blockers, rollback, evidence locations, and next safe action.

The authority ladder

Documents can describe, authorize, report, or prove. Those are different jobs.

  1. Newest approved narrow spec
    controls only explicit conflicts.
  2. Older specs remain active
    for every non-conflicting rule.
  3. Kickoff grants action
    planning alone does not launch a build.
  4. README / progress report state
    they do not manufacture proof.
  5. Dated evidence proves results
    and preserves failures honestly.

New direction is not deployed state. Provider acceptance is not delivery. A mock is not a live integration. Historical evidence is never rewritten.

03 / Coding standards

Make the repository explain itself.

The standard is designed for the next human or agent arriving with zero tribal knowledge. Select a discipline to see the working rules and its exit gate.

No dark code. No silent failures. No oral history required.

Every module states what it does, what it depends on, who depends on it, and why it exists. The code, tests, CLI, evidence, and commit history form one explainable system.

WHATThe exact failure
WHEREModule + context
HOWThe next remedy
